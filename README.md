# 路灯调光能耗审计（单页）

纯前端单页 + Node 20 零依赖静态服务，无任何框架和第三方包。

## 运行

```bash
node server.js          # 默认 8080，也可 node server.js 8090
# 浏览器打开 http://localhost:8080/
```

重新生成样例、核对计算：

```bash
node scripts/generate-sample.js   # 确定性随机，重跑得到同样的 100 盏灯
node scripts/verify.js            # 月历/曲线/单灯/改档/审计的逐步断言
```

## 数据

- `data/lamps.json`：灯具台账（编号、所属回路、经纬度、功率 kW、光源类型、投运日期、电价 0.62 元/kWh）。
- `data/curves.json`：回路（多边形区域）、调光曲线（一天若干时段 + 亮度百分比）、曲线生效记录（回路 × 曲线 × 起止日期；一条曲线可套多个回路）。

样例：100 盏灯、12 条回路、5 档曲线。内置问题数据供审计演示：

- 1 组同一回路同一时刻两条生效曲线（`C4` 全年 `K3` 与 6~8 月 `K5` 重叠）；
- 5 盏坐标异常灯：2 盏落在两条回路上、1 盏不落任何回路、1 盏所属回路与实际落区不符、1 盏远处游离灯。

## 口径（页面顶部同样明示）

- **亮度折算：线性折算**。功率系数 = 亮度% / 100，50% 亮度按 50% 功率计电，**不做光通量补偿**。
- 单灯区间能耗 = `功率(kW) × Σ(时段小时 × 亮度%/100) × 生效天数`，电费 = 能耗 × 0.62。
- 天数按**自然月**：投运日和区间端点按自然日包含法，二月、大小月、跨年均逐日计算，不用 30 天一口价。
- 亮灯率 = `亮度加权点亮分钟 ÷ (计划点亮分钟 × 100)`（即计划时段内的平均亮度水平）。
- 同一时刻有多条生效曲线属于数据错误（审计报红）；基准方案的取数口径是“开始日最晚”的一条，页面上有说明。
- 跨 0 点时段自动拆段；曲线时段互相重叠会报错。

## 页面操作

1. 平面图按经纬度画 12 个回路多边形和 100 个灯点；点回路多边形、图例或对比表行即可高亮该回路的灯（异常灯红圈）。
2. “回路详情”里可分别给**方案 A / 方案 B** 选当前档位，逐步验算、灯表与下方两张能耗表立即重算。
3. 对比区并排展示两套方案的总能耗、总电费、总亮灯率，以及按回路的能耗/电费/亮灯率，按 `|电费差|` 从大到小排序。
4. 顶部可改分析区间和基准取数日；月历条显示区间内每个自然月的实际天数。

## 验收示例（与 `scripts/verify.js` 一致）

选 `C1`，方案 A 保持 `K2 半夜节能`，方案 B 改成 `K5 人少即灭`：

- `K2`：18:30–22:00（210 min ×100%）+ 22:00–06:00（480 min ×60%）= 加权 49 800 min = 8.300 h/日；
- `K5`：150 min ×85% + 450 min ×20% + 90 min ×60% = 27 150 min = 4.525 h/日；
- 单灯（如 0.10 kW、2026 全年生效）：A = 0.10 × 8.300 × 365 = 302.95 kWh，电费 187.83 元；
- 全回路合计 B 比 A 少 1 861.26 kWh、少 1 153.98 元，A 表数字不变，C1 排到差幅第一。

## 目录

- `server.js`：零依赖静态服务（仅暴露 `web/`、`data/`，含路径穿越防护）。
- `web/core.js`：无 DOM 依赖的计算内核（月历、射线法点在面内、审计、方案能耗）。
- `web/app.js` / `web/index.html` / `web/styles.css`：单页界面。
- `scripts/generate-sample.js`：样例生成；`scripts/verify.js`：口径断言。
